# Reproducing CFDaAI on NERSC

This document serves as a guide for installing and running the full
sim and train loop.

> This guide uses the home filesystem to host the code. Then, the scratch
> filesystem is used for holding the logs and results.

### Obtain code
1. From GitHub
```
git clone https://github.com/radical-collaboration/xGFabric.git
cd xGFabric/demo2/nd/CFDaAI/
```

### Install dependencies

1. Install cspot if not already on path.
```
# easiest way is to use the install script

cd /global/common/software/<PROJECT_ID>/
mkdir -p cspot/build/bin
cd cspot/build/bin
wget https://raw.githubusercontent.com/MAYHEM-Lab/cspot/refs/heads/caplets/dist/update-cspot-distribution.sh
chmod +x update-cspot-distribution.sh
./update-cspot-distribution.sh
export PATH="${PWD}:${PATH}"
echo "export PATH=\"${PWD}:\$PATH\"" >> ~/.bashrc
```

2. Obtain cups_structure.zip
```
cd <GIT_REPO_ROOT>/demo2/nd/CFDaAI/
wget http://sites.cs.ucsb.edu/~benjamincarter/xgfabric/cups_structure.zip 
mv cups_structure.zip simulation/
```

3. OpenFOAM
```
module load spack
spack install openmpi@4.1.5
```


### Create conda environments
1. Main python environment

```
cd <GIT_REPO_ROOT>/demo2/nd/CFDaAI/
conda create python=3.12 -f utils/environment.yml
conda activate cfdaai
```

2. XGFabric Environment - for running sims.
```
# notice different path here:
cd <GIT_REPO_ROOT>/demo1/nd/
conda create python=3.12 -f environment.yml
```


### Create link to scratch space 
This allows for using scratchspace to host the results and logs.
```
mkdir $SCRATCH/xgfabric
cd <GIT_REPO_ROOT>/demo2/nd/CFDaAI
ln -s $SCRATCH/xgfabric scratchspace
```

### Edit config.sh
```
cp config_template.sh config.sh
```
Fill in variables as needed.

Note: the workflow pushes models to a CSPOT endpoint. There is a default one in
the config template, but if you want to run this with your own CSPOT endpoint,
refer to the CSPOT docs on how to set up a file WooF.


### Verify environments
Verify that the conda environments, OpenFOAM, and other items are accessible
1. Start an interactive prompt via:
`salloc --nodes 1 --time 00:15:00 --qos interactive --constraint cpu --account PROJECT_ID`
2. Remaining steps are in the interactive prompt.
3. Run `conda activate cfdaai`
4. `cd <GIT_REPO_ROOT>/demo2/nd/CFDaAI/`
4. Run `senspot-file-recv`. Should return a short help text (eg. you should not
   get 'command not found')
5. Run `test_environment.sh`. Should be successful (ok if it warns about conda
   init before conda activate, or a warning on onloading the cpe module).
6. Exit interactive prompt


### Run Complete Workflow
> Takes about ~3-4hrs waiting in slurm queue from my experience.
```
nohup bash main.sh &
```

## Debug tips:
Instead of running with coordinator / 72 nodes, run makeflow and work queue
manually with an interactive session.

1. Setup:
- Activate the `cfdaai` conda environment
- Run `python utils/coordinator.py --generate-makeflow-only`
- Locate the makeflow file generated. 

2. Open two terminals, both in the working directory of the repository.
3. In the first terminal, start an interactive session.
```
salloc --qos interactive --time 01:00:00 --qos interactive --account PROJECT_ID --constraint gpu --nodes 1
```
> I am using gpu here as it allows for both sims (cpu) and training (gpu) to
> run.

4. Once the salloc opens, open a tmux session with two panes. Run `conda
   activate cfdaai` in both panes.

5. Meanwhile, in the second terminal, start makeflow:
```
makeflow -T wq -N my_cfd_run relative/path/to/makeflow/from/setup.makeflow -d all -P 1
```

5. Back to first terminal, start work_queue in one pane
```
work_queue_worker -M my_cfd_run --max-backoff=10 --cores 128 --gpus 1 -d all
```

6. Watch logs generated by the tasks in the other pane in
   `/tmp/worker_<SOME_WORKER_ID>`

7. If there is a problem with a task, you can stop the work_queue_worker and run
   the task directly (log will show you the command).
